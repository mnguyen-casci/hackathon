Context optimization benchmark

Context Ledger

Same bug, same model, seven ways of feeding it context. A one-line pricing bug (PLATINUM customers getting the same loyalty discount as GOLD instead of double) in a 15-file Java order-processing service was fixed by Claude Sonnet 5 seven separate times — from dumping every file into the prompt, to keyword retrieval against a realistic bug report, to tool-based exploration with an auto-generated context file or call graph, to a forced low compaction window. All seven ran concurrently and were graded blind by a separate judge model (Opus, not Sonnet, to avoid a model marking its own homework).

Cheaper doesn't mean worse, and "optimized" doesn't always mean cheaper

All seven variants correctly diagnosed and fixed the bug in LoyaltyService, all seven left mvn test passing, and a separate, tougher judge model (Opus, blind to which strategy produced each fix) scored every one 8/10 or higher — correctness wasn't traded away by any strategy here. The differences are entirely in cost and turns.

RAG-lite genuinely won, and this time on a realistic query: instead of feeding it the failing test's own assertion text, the retrieval step was given a plain-language bug report a customer or QA person might actually write, with none of the code's exact vocabulary in it. It still surfaced LoyaltyService.java through ordinary domain-word overlap and answered in one shot, cheaper than naive despite solving the same task. That's the clean success story, and it held up under a harder, more honest test than the first pass of this benchmark used.

The rest is more nuanced: every tool-based strategy (jit-loading, dependency-graph, context-file, compaction) landed in a similar cost band, all noticeably above naive and rag-lite, because they spend multiple turns exploring and each turn re-sends the growing conversation. Cache reads are cheap per token but not free. Many-tools cost more too, and here the comparison is cleanly isolated: it's given the exact same file tree and task as jit-loading, with the full default toolset described instead of five, but the heavier tools (Bash, web access, subagents) are explicitly denied so it can't actually behave differently, only pay for describing tools it never uses. The gap that remains is real tool-schema overhead, not a side effect of extra exploration.

The dependency-graph and context-file variants are also no longer hand-curated best cases: both are generated by a small script that scans the actual source text (no real Java parser), the kind of mechanical, slightly imperfect output real tooling would produce. It even picked up a false PaymentService → OrderProcessor edge purely from a code comment mentioning "the OrderProcessor pipeline" in prose. Despite that imperfection, both still performed in line with plain jit-loading.

The honest read: on a single, small, self-contained bug fix, a good retrieval step beats both brute-force dumping and full agentic exploration, even when the query is realistic rather than leading. Tool-based strategies still matter — for tasks too large to dump or retrieve cleanly, and for tool-schema lazy loading specifically, where the isolated many-tools comparison shows a real, direct cost. But "give the agent more autonomy and let it explore" was not the cheapest path here, and it's worth showing that rather than averaging it away.

What the columns mean

Turns
How many back-and-forth trips it took with the model. One turn means it answered immediately; several means it had to look around, then act, then maybe look again.
Cache write
Tokens spent the first time the AI sees something in that conversation, like photocopying it into memory. Costs a bit extra since it's brand new.
Cache read
Tokens spent glancing back at something already photocopied into memory. Much cheaper than writing it fresh.
Output tokens
The AI's own writing: its answer, its reasoning, the code it produced.
Cost (USD)
The real dollar total, from how much of each token type above got used (writes and fresh reads cost more per token than cache reads).
Wall time
How many real-world seconds it took, measured with each strategy running alone so nothing skews it.
Test
A plain yes/no: did the actual automated test suite confirm the bug is really fixed?
Quality
A separate AI, acting as an independent referee who doesn't know which strategy produced the fix, grades it 1-10 on correctness, minimality, and code style.
Judge rationale
That referee's one-sentence explanation for the score it gave.

Produced by running the bundled Claude Code CLI headlessly (claude -p --output-format json --tools "...") against a fresh temp copy of the sample project per variant, on Claude Sonnet 5, one run per variant. The harness can run all seven concurrently for speed (each is fully isolated, no shared state), but these numbers are from a sequential run instead: concurrent mvn test calls compete for real CPU/disk and inflate wall-clock time with noise unrelated to any context strategy, so wall time here reflects each variant running alone. Token, cost, and quality figures are identical either way, concurrency doesn't change what happens inside any one variant's own conversation with the model. No separate Anthropic API key was used — this runs against whatever account is already authenticated in Claude Code. Quality scores come from a separate judge call on Opus (not Sonnet) shown only a unified diff of the fix, blind to which strategy produced it. RAG-lite's retrieval query is a realistic bug report with none of the buggy code's exact vocabulary, not the failing test's own assertion text. Dependency-graph and context-file are generated by scanning the source text (no real Java parser), not hand-written. Many-tools uses --tools default with the heavier tools explicitly denied, isolating tool-schema description cost from behavioral change. The compaction variant forces --autocompact 100000 (the CLI's minimum); a --debug diagnostic run confirmed it reached the 80%-of-threshold warning level by the third turn but did not actually trigger before the task finished, the task's natural token growth sits right at that threshold, so whether it fires is inconsistent run-to-run.
